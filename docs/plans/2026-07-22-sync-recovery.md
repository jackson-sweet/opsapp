# SYNC RECOVERY Implementation Plan

> **For Claude:** Executed subagent-driven in-session: Fable orchestrates + reviews; each task runs as an Opus agent (`model: "opus"`). Spec: `docs/superpowers/specs/2026-07-22-sync-recovery-design.md` — every agent reads it first.

**Goal:** No locally-created work is ever invisible or unrecoverable: classify sync errors (4xx park / 5xx retry+backoff), re-enqueue on restart, fix the auto-lead 400 and deck-design orphaning at the server, and ship the PENDING WORK recovery screen.

**Architecture:** Pure policy seams (SyncErrorClassifier, RecoveryInventory, SyncStatusCopy) + minimal mutations to the two mirrored outbound paths; a new status VALUE (`"parked"`) instead of a SwiftData schema change; server fixes are two additive prod migrations.

**Tech stack:** SwiftUI/SwiftData (iOS 17.6 target), supabase-swift, Postgres (plpgsql, PostgREST), XCTest (+ existing snapshot harness pattern).

**Design system:** `ops-design-system/project/DESIGN.md` + `mobile/MOBILE.md`; iOS tokens ONLY via `OPS/Styles/OPSStyle.swift`. Zero hardcoded values.

**Required skills (by task):** ops-design + mobile-ux-design (T6), ops-copywriter (T6 strings — final copy supplied in brief), audit-design-system (T7).

**House rules for every agent:** preserve CRLF/existing line endings; lowercase UUIDs at generation; no AI attribution in commits; conventional commits; stage ONLY your own files by name (`git add <paths>`; never `-A`); do not touch `OPS.xcodeproj/project.pbxproj` (file-sync project — new files auto-register; the existing pbxproj diff belongs to a sibling session); test runs use a task-private DerivedData dir `-derivedDataPath .dd-syncrec-<task>` with `-destination 'platform=iOS Simulator,name=iPhone 17,OS=26.5'`; device build verification is Fable's job in T7, not yours.
