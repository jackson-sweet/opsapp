# Phone conflict protocol verification

The focused harness compiles the actual Foundation command codec, actual SwiftData template/answer/operation models, write-value builders, date parser and template draft logic. It executes 10 XCTest cases, including a persisted SQLite store reopened with a new ModelContainer and an independent ModelContext read. See command-tests.log and run-command-tests.sh.

It does not compile SiteVisitVersionedSync, the whole app, SwiftUI review, the recovery vault or outbound queue integration. All changed Swift sources passed the Swift parser. App-hosted tests were added for immutable attempted queue payloads, unattempted coalescing, actor-scoped template/resolution vault custody and corrupt-archive rejection; they require the isolated iOS build baton to execute. No signed-client/device claim follows from the macOS tests.

The new SiteVisitConflictReview component uses OPSStyle typography, text/text2/rose, spacing1/2/3, glassSurface and existing primary/secondary button styles. Source token scan found no new literal colors, font sizes, spacing or corner radii in that component. It adds no custom motion. Existing PendingWorkDetailSheet retains its pre-existing styles. Visual/simulator proof is still required before client-release acceptance.

Server protocol proof is in the sibling web worktree tests/sql/site-visit-workflow-run.sh and docs/artifacts/phase19/phone-protocol-tests.log. It uses a disposable PG17 Unix-socket cluster, actual captured permission function definitions, local actor/tenant/role rows, representative live restrictive RLS policies and concurrent PostgreSQL sessions. It does not use production data writes or activate any production company.
